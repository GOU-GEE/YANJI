# 一、M2 与 M3 分工

## M2：确定性三设备测试框架

建立：

```text
device_a.sqlite
device_b.sqlite
device_c.sqlite
```

每个设备拥有独立：

```text
Device ID
Ed25519 Identity
ClockState
Oplog
Projection
Frontier
Membership State
```

不得：

```text
三个设备共用同一个内存 Repository
```

也不得：

```text
直接复制 SQLite
```

设备之间只能通过：

# Signed Operation

进行数据传播。

---

## M3：随机化收敛测试

在 M2 Harness 上：

```text
随机生成业务操作
随机决定在哪台设备执行
随机决定网络是否可达
随机决定 Operation 投递顺序
随机插入重复
随机延迟
随机重启设备
随机发生设备撤销
```

然后恢复全连接并交换全部合法 Operation。

最终验证所有设备收敛。

# 二、建立 DeviceHarness

建议建立类似：

```text
TestDevice
```

拥有：

```text
name

databasePath

deviceIdentity

workspaceId

OperationWriter

OperationApplier

OriginLookup

ProjectionStore
```

提供测试 API：

```text
execute(command)

exportAvailableOperations()

receive(operation)

restart()

digest()

frontier()

pendingState()

invariantCheck()
```

`restart()` 必须：

```text
关闭 SQLite
销毁当前 Dart 对象
重新打开数据库
重新加载 Clock / Identity / State
```

不是简单重新创建 Repository 指针。

# 三、建立模拟网络

不要在 M3 写真正 Socket。

建立：

# SimulatedTransport

维护：

```text
A → B queue
A → C queue
B → A queue
B → C queue
C → A queue
C → B queue
```

每个队列存：

```text
signed operation bytes
signature
source peer metadata
```

支持：

```text
deliverNext()

deliverRandom()

deliverAll()

duplicate()

delay()

dropDeliveryAttempt()

partition()

healPartition()
```

注意：

# drop 只能表示本次传输失败。

不能从 Origin 的 Oplog 中真正删除 Operation。

恢复连接之后：

Frontier Diff 必须能够重新补齐。

---

# 四、不要让模拟网络知道业务含义

Transport 只处理：

```text

signature
peer
```

不能：

```text

如果是 Delete 就优先发送
```

否则测试会掩盖真正同步问题。

# 二十八、不要永久随机丢 Operation

M3 中：

```text
drop
```

定义为：

> 某一次 packet/delivery attempt 失败。

最终进入：

# convergence phase

时必须允许 Frontier Diff 补齐所有合法历史。

否则测试的不是 Eventual Consistency，而是：

> 永久数据丢失后的魔法恢复。

协议没有义务恢复从所有设备上都永久消失的数据。

# 二十九、Convergence Phase

随机 workload 结束后：

停止生成新业务 Operation。

然后：

```text
heal all partitions
```

反复执行：

```text
A ↔ B
A ↔ C
B ↔ C
```

Frontier Diff + Gossip。

直到：

```text
本轮没有任何新的合法 Operation 可传输
```

或者达到明确 iteration upper bound。

如果超过 upper bound：

测试失败，报告：

```text
seed
frontiers
pending states
```

不能无限循环。

# 三十四、第五层：Invariant Check

每台设备运行：

```text
invariantCheck()
```

至少检查：

```text
没有悬空 FK Projection

completed Session 无 open Segment

一个 Session 最多一个 open Segment

Session Segment end >= start

非 Owner Operation 未影响 Timer 状态

被 Tombstone 删除实体不可 materialized

unauthorized_revoked Operation 不影响 Projection

pending_schema 不影响 Projection

FieldClock winner 指向有效 Operation

MV active version 均为因果极大版本
```

任何一条失败：

整个 Seed 失败。

M3 结束时，我们应该能够做一个非常强的断言：

> 给三台研迹设备任意合法的离线编辑、冲突、重复传播、乱序传播、分区和重新连接，只要所有合法 Operation 最终能够传播到所有设备，那么所有设备的业务状态都会确定性地收敛到相同结果。

这就是 M2/M3 唯一真正重要的验收目标。
