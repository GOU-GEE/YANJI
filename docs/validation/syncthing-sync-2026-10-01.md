# 已配对设备自动同步：实现与验证

## 已实现行为

应用内置 Syncthing v2.1.5；用户无需另外安装 Syncthing。首次配对继续使用现有局域网扫码和双向确认流程，之后复用配对证书与设备身份，自动寻找已配对设备。优先直连，无法直连时使用 Syncthing 公共中继。不部署开发者服务器，但跨网络连接仍依赖第三方公共发现/中继的可用性，两端需要同时具备运行机会；中继不替离线设备长期保存历史。

打开应用、回到前台和本机修改后触发同步；运行中每 5 秒继续处理导入和确认。后台尽力执行，系统挂起后等待再次进入前台。前台停留 15 秒仍有设备未确认时提示保持双端打开，支持手动等待同步（默认最多 30 秒）。个人页按设备显示待同步记录，手动按钮等待过程中防止重复点击。连接失败不会阻止本机记录保存。

## 数据保护

- SQLite 已提交的签名操作日志是本机权威数据，绝不共享 SQLite 文件。
- 每个操作生成独立不可变 `.op` 文件，以 SHA-256 命名；写入时先刷新 `.partial` 再改名。
- 收到文件后检查内容散列、原有 Ed25519 签名、学习空间和设备授权；同一操作重传由数据库去重，未满足授权的操作等待信任链补齐。
- 接收端数据库事务提交后才生成签名 `.ack`。按每个来源设备的连续序号确认，缺口之后的记录不会越过缺口确认。全部已配对且有效的设备均确认，界面才显示全部完成。
- 缺失/损坏的交换文件由本机日志重建；传输文件删除不转换成业务记录删除。损坏文件单独报错，其余有效记录继续导入。撤销配对同步更新原生共享设备列表；无剩余配对设备时停止引擎。
- 确认缓存仅保存可重新校验的签名内容，不把缓存当作数据库已导入的证据。重启、缓存损坏后可以重复验证、补传。
- 自动生成独立的签名历史备份，每 24 小时一次；备份位于交换目录之外，不受 Syncthing 的删除传播影响。`OperationFileExchange.restoreBackup` 可向同空间、已授权的安装恢复历史，恢复仍经过签名验证和去重。当前未提供面向用户的备份导出/恢复页面。

这不能保证所有设备被卸载、存储损坏或同时丢失后仍可恢复。独立备份当前仍在本机应用支持目录；卸载应用可能删除它。没有外部存储，也没有其他仍保有数据的设备时，不存在凭空恢复的来源。备份不包含安装私钥，不能用它替代身份恢复或重新配对。

传输保留 TLS 与操作签名。公共中继不能读取计时记录；Syncthing 管理页面、自动升级、使用统计和崩溃报告均禁用。首次尚未配对的安装不启用公共发现。公网设备发现服务会获得设备发现所需的证书设备标识和网络地址。

## 原生构建

源码：`packages/yanji_syncthing/native`。桥接：Android Kotlin、iOS/macOS Objective-C、Windows 的应用内子进程（无需安装其他软件）。单个应用进程只运行一个原生节点。

生成的引擎二进制位于被忽略的 `packages/yanji_syncthing/native/build`，不提交到仓库。使用 Go >= 1.26.2、Apple Xcode、Android SDK/NDK，根据平台先构建：

```sh
python3 tool/build_syncthing.py apple
python3 tool/build_syncthing.py android
python3 tool/build_syncthing.py windows
flutter pub get
```

脚本下载并验证官方 Syncthing v2.1.5 源码归档，SHA-256 为 `1b3e217022848b65a1b7ececa4d5e752fc044b4e8643befa1f9a8a9dc9b2bbbf`。Go 模块通过本地 replace 使用该源码，模块声明中的 v1 版本是满足上游模块路径要求的占位，不是实际引擎版本。gomobile/gobind 固定为 `v0.0.0-20260908204917-8b95e45f8d3e`。Android 打包提取 AAR 内的 classes/JNI，避免嵌套 AAR。Windows 仅打包 amd64 引擎，资产仅在 Windows 构建中包含；尚未验证 ARM64 Windows。

引擎遵循 MPL-2.0，许可证随插件源码提供。发布二进制时，应随发行物提供许可与相应源码的获取方式，源码来源为 https://github.com/syncthing/syncthing/tree/v2.1.5，桥接源码位于本仓库。

## 验证记录

- 应用层 6 项专项测试通过：三设备离线新增和逐设备确认；重复导入和重启；损坏、删除、半文件与损坏缓存；伪造确认拒绝；完整备份与恢复；已配对非根设备重开；引擎失败/超时不丢记录与撤销共享（部分场景组合在一项测试中）。
- application/protocol 与统计页相关回归测试通过（最终批次 60 项）。
- 独立原生进程：真实 TLS 双向传输、离线积压后接收端重启补传、撤销接收端后不再传输，均通过。运行命令：`python3 tool/build_syncthing.py harness`，`python3 tool/test_syncthing_nodes.py`。
- iOS 模拟器 Debug 构建通过；设备桥接集成测试验证启动、配置、扫描、停止、相同目录重启，通过。更新应用读取既有学习空间的启动检查也通过。最终恢复原有 YANJI_PREVIEW 版本，保留模拟器预览数据。
- Android Debug APK 构建通过（已有玻璃效果 shader 的 Skia 兼容警告仍存在，与同步无关）。已在 USB 连接的 RMX3820 真机通过原生桥接集成测试（启动、配置、扫描、停止、相同目录重启）。已覆盖安装应用，保留原数据。仍未验证实机后台限制及实际跨 WiFi 传输。
- macOS 编译与链接通过（以关闭代码签名的构建验证；标准构建受本机开发证书配置限制）。
- Windows amd64 原生引擎交叉编译通过；未在 Windows 主机验证整个 Flutter 应用。
- **未进行图书馆/家庭两个实际 WiFi、公共中继以及两台真机的端到端验收。** 网络封锁、公共服务不可用和系统挂起时，会保留本机数据，显示待同步并等待重试；不能保证每种网络都可建立连接。
