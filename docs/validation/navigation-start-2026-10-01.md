# 导航玻璃块起步连续性

2026-10-01：修正按住内部玻璃块、刚开始拖动时的一帧跳变。

原因：原来采用 `DragStartBehavior.down`，识别拖动时一次性应用此前积累的手势识别位移；拖动状态又将折射强度从 0 直接切到 1，速度直接驱动拉伸，外层导航条还叠加了单次位移的即时变形。

改动：

- 使用 `DragStartBehavior.start`，识别后的位移连续跟随，不一次性补上识别前累积位移。
- 拖动折射在 120ms 内平滑进入，停住手指时仍保持完整折射。
- 速度拉伸通过 80ms 平滑跟随；外层导航条用弹簧跟随累计拖动量，移除单次位移的瞬时放大。
- 结束/取消时平滑恢复，系统减少动态效果时直接清除这些过渡。

验证：67 项 widget 测试通过。新增横向/纵向起步逐帧检查：长按保持后跨过拖动识别距离，位置变化小于 1、尺寸连续、折射初值为 0；下一帧折射处于 0–1，继续小幅拖动时尺寸不立即跳变，最终完整折射且取消后恢复。

模拟器验证在既有真实导航栏光学脚本中增加同样的按住起步检查，覆盖深浅色、图标交叉边缘及松手提交。[截图目录](navigation-start-2026-10-01/)保存真实渲染样本。这里验证交互连续性，不作为真机帧率测量。

结束后恢复正常 `YANJI_PREVIEW` 应用并保留已有 mock 数据。
