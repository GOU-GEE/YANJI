# 已配对设备重复同步修复（2026-10-01）

## 问题和修改

配对只保存当时的 IP/端口。TLS 监听使用随机端口，应用重启或网络地址变化后，持久化的地址可能无法连接。

新增 `LanPeerDiscovery` 和原生 Bonjour/Android NSD 实现（Bonsoir 7.1.5），发布 `_yanji-sync._tcp` 服务及当前 TLS 监听端口。广告只包含协议版本和设备 ID 的 SHA-256 截断提示，不发布学习内容、工作区名称、密钥或完整设备 ID。系统负责网卡地址解析，应用恢复前台时重新发布。每次手动同步重新浏览，最多等待三秒收集已授权设备的地址，优先连接发现的新地址，失败时尝试上一次验证过的地址。连接和同步验证成功后才持久化新地址。iOS/macOS 已声明 Bonjour 服务及本地网络用途。

发现结果只提供连接地址。TLS 仍固定配对时确认的证书指纹，Ed25519 身份仍来自授权链。旧 Genesis 的根设备没有证书指纹，继续使用配对二维码确认并保存在安全存储中的指纹。

另修复接收端要求 TLS 客户端证书、但传输层未配置客户端证书的问题。手动同步认证改为版本 2：保留固定服务端证书和双方身份签名，接收端额外生成随机挑战，发起端必须签署包含该挑战和双方身份的证明，验证通过后才交换学习历史。捕获旧的初始签名不能授权新会话。TLS 握手失败不会终止监听。

两台设备都需要更新应用；保留现有配对与数据。此认证版本变更不改变操作日志格式、二维码格式或历史记录。

## 验证

7 项相关 Flutter 测试通过，覆盖：

- 首次配对与三设备授权历史转发。
- 真实本机 TLS/SQLite 的双向增量交换，以及没有新数据时同步成功。
- 双端重启同步协调器、强制分配新监听端口、把缓存 IP 改为过期地址后，通过新发现地址同步并保存更新。
- 未授权设备发现过滤、伪造地址的证书拒绝、发现不可用时使用已验证缓存、设备离线和撤销后的同步拒绝。
- 缺少有效随机挑战证明时不发送历史。
- 原生发现接口事件模拟：解析、更新、丢失、无效记录过滤以及发布/浏览会话释放。
- TLS 证书固定、TLS 身份存储与授权链回归。

修改涉及的同步、应用生命周期和新测试静态检查通过。iOS 模拟器调试构建、Android APK 调试构建通过。

本轮使用本机真实 TLS 和模拟的服务发现事件，没有声称完成两台真机之间的 Bonjour/NSD 或真实 Wi-Fi 切换验收。最终真机验收：双端更新、同一可互访 Wi-Fi、允许本地网络、双端打开研迹；首次配对后退出并重开双端，分别新增学习记录，再从一端「我的」右上角同步，确认双端记录一致；切换到另一 Wi-Fi 后重复。
