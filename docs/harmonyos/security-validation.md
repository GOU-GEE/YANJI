## 测试清理事故与隔离修正

早期测试曾作为正式包名 `com.example.yanji` 下的 `entry_test` 模块安装。
故障用例本身及随后本机冒烟均通过；但在执行
`bm uninstall -n com.example.yanji -m entry_test -k` 后，旧模拟器
`Yanji_API26_6G` 的 HUKS 包装密钥不可用，数据库及密文仍在。即使带保留数据选项，
也不能把同包名测试模块的卸载视为不影响正式凭据的清理操作。

旧实例未重置、未清除数据，已停机保留。新增
`harmonyos_key_loss_startup_test.dart` 在该实例验证：正式应用组合入口及身份
读取均返回 `CREDENTIAL_KEY_MISSING`，不生成替代身份，SQLite 主文件和现有
WAL/SHM 文件的前后 SHA-256 一致。界面将密钥丢失与临时不可读区分，
明确提示保留学习记录、不要清除应用数据。旧密钥没有恢复，旧实例不能正常进入学习页。

修正后的测试包使用独立 bundle，不再向正式包安装测试模块。在全新
`Yanji_API26_Validation` 实例创建合成工作区、身份及 TLS 凭据后：
独立测试应用的 8 项用例通过，随后卸载**独立测试应用**；正式应用强杀重启仍通过，
设备 ID、公钥、TLS 指纹与工作区 ID 均与测试前一致。此结果验证了安装、运行、
清理测试包的完整隔离，而不是仅依赖别名不同。

## 复现

先启动并解锁一次性模拟器，再连接其调试端口：

```sh
tool/run_harmonyos_native_tests.sh 127.0.0.1:10001
```

脚本构建并安装独立包名的未签名测试 HAP，通过官方 `aa test` 运行测试。
不要将正式工程的 `entry_test` 模块安装到已有研迹数据的应用中，也不要对正式包
执行测试模块卸载。脚本不卸载正式应用或模块。
它检查安装结果和真实测试汇总：必须 8 项全部通过且无错误、失败或跳过，
否则以非零状态退出。不能只看 `hdc` 或 `aa` 的退出码——它们可能在测试全错时仍返回 0。
失败报告已用于反向验证结果检查，不会被误判为通过。

日志和 JSON 汇总位于忽略的 `work/harmonyos/native-security/`。
单独构建隔离测试应用可运行 `tool/build_harmonyos_native_tests.sh`。

## 验收边界

已验证的是模拟器内的真实原生调用、密文故障和测试 key 删除。
没有模拟真实 TEE/安全硬件故障、系统升级/备份恢复、磁盘满或断电写入失败，
也没有替代真机签名、最低系统版本和真机长时间运行验收。
